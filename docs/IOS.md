# Escanor on iPhone

The iPhone app is the same web app as Android, inside Capacitor's iOS shell (`packages/web/ios`). **It has not been run on an iPhone or a
simulator by us** (there is no Mac in this project's toolchain); what is verified is that the web code passes its tests with the iOS
platform simulated, and the Xcode project is generated by Capacitor's own tooling. The first Mac build is the real test.

## Build it (needs a Mac with Xcode 16+)

```bash
npm ci
cd packages/web
npx vite build && npx cap sync ios
open ios/App/App.xcodeproj      # Product > Run on a simulator or your iPhone
```

No Mac? **Actions > iOS build > Run workflow** builds for the simulator on a GitHub Mac runner, runs the web tests, launches the app and
uploads a screenshot. (It needs GitHub Actions minutes: the account's billing must be in good standing.)

## What works, and what iOS does not allow

| | iPhone |
|---|---|
| Sign in, chats, Connections, Computers (pair by code or QR), Machines, billing, Settings | yes (same code) |
| QR scanning | camera scanner in the page (`jsQR`); the native ML Kit scanner is Android only |
| Talk to Escanor (microphone button, voice mode, dictation, spoken answers) | yes, through iOS speech recognition and text to speech |
| Call someone by name | yes, but iOS always shows its own Call confirmation; fuzzy contact matching works |
| Open websites, torch | yes |
| Open another app by name, set alarms or timers, change the volume | **no**: iOS gives apps no way to do it. The assistant says so |
| Control the phone (tap, scroll, read the screen) | **no**: there is nothing like Accessibility for third-party apps |
| "Hey Escanor" in the background | **no**: iOS does not let an app listen in the background |
| Push notifications | not yet (needs the Apple steps below) |

The Android-only parts are hidden from Settings on iPhone, with a line saying why.

## Before it can go to TestFlight / the App Store

1. An Apple Developer account, a signing team set in Xcode (Signing & Capabilities), and the bundle id `io.visey.remoteharness` (or a new one).
2. Push: create an APNs key, upload it to the Firebase project (`escanorai`), add an iOS app there, put `GoogleService-Info.plist` in `ios/App/App`,
   enable Push Notifications and Background Modes in Xcode, and let the backend send to iOS tokens (they are FCM tokens once Firebase is wired
   into the iOS app). Until then the app does not ask for notification permission on iOS.
3. Privacy: App Store Connect "App Privacy" answers follow the Google Play data safety form; the usage strings are in `Info.plist`.
4. Sign in with Apple is required by App Store rules **if** other third-party sign-in (Google) is offered. The backend would need an Apple
   provider; this is not built.
